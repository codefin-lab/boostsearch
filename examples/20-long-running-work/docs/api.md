# API surface -- 20. Work that takes longer than a request

Every request this example makes, in the order it makes them. Taken
from `run.sh`; if the two disagree, `run.sh` is right. Requests made by the
checks (`_count`, and the polling in `follow`) are listed where they happen.

| Step | Method | Path | Body |
|---|---|---|---|
| an index of parcels, on two shards, refreshed only when asked | `DELETE` | `/$IDX` | -- |
|  | `PUT` | `/$IDX` | `requests/01-parcels-on-two-shards.json` |
|  | `GET` | `/_cluster/health/$IDX?wait_for_status=yellow&timeout=5s` | -- |
| six thousand parcels, generated so the jobs have something to work through | `POST` | `/$IDX/_bulk?refresh=true` | generated by `run.sh`, 6000 parcels |
|  | `GET` | `/$IDX/_count` | -- |
| a job sent off rather than waited for: the answer is a task id | `POST` | `/$IDX/_count` | inline |
|  | `POST` | `/$IDX/_update_by_query?wait_for_completion=false&refresh=true` | `requests/02-add-the-remote-area-surcharge.json` |
| following it by id until it says it has completed | `GET` | `/_tasks/<task id>` | -- (repeated once a second until `completed`) |
|  | `POST` | `/$IDX/_count` | inline |
| a job told how fast it may go: requests_per_second | `POST` | `/$IDX/_update_by_query?requests_per_second=2000&scroll_size=500&refresh=true` | `requests/03-mark-every-parcel-audited.json` |
|  | `POST` | `/$IDX/_count` | inline |
| the dispatch app marks 40 parcels delivered, and nobody refreshes | `POST` | `/$IDX/_update/TH000150` ... `/$IDX/_update/TH006000` (40 calls) | `requests/05-the-dispatch-app-marks-a-parcel-delivered.json` |
|  | `POST` | `/$IDX/_count` | inline |
| a repricing job with conflicts: proceed, sent off and followed | `POST` | `/$IDX/_update_by_query?wait_for_completion=false&refresh=true` | `requests/04-reprice-by-weight-band.json` |
|  | `GET` | `/_tasks/<task id>` | -- (repeated until `completed`) |
|  | `POST` | `/$IDX/_count` | inline |
| the same collision without conflicts: proceed -- the job stops after the batch that met one | `POST` | `/$IDX/_update/TH000075` ... `/$IDX/_update/TH005925` (40 calls) | `requests/06-the-dispatch-app-marks-a-parcel-returned.json` |
|  | `POST` | `/$IDX/_update_by_query` | `requests/07-the-same-job-without-conflicts-proceed.json` (answers 409) |
| nothing is left running once the jobs have answered | `GET` | `/_tasks?actions=*byquery&detailed` | -- |
| the .tasks index: where a finished task's result outlives the request | `POST` | `/.tasks/_refresh` | -- |
|  | `GET` | `/.tasks/_doc/<task id>` | -- |
|  | `GET` | `/.tasks/_search` | `requests/08-task-results-that-met-a-conflict.json` |
| a delete by query, sent off and followed the same way | `POST` | `/$IDX/_refresh` | -- |
|  | `POST` | `/$IDX/_count` | inline |
|  | `POST` | `/$IDX/_delete_by_query?wait_for_completion=false&refresh=true` | `requests/09-purge-cancelled-parcels.json` |
|  | `GET` | `/_tasks/<task id>` | -- (repeated until `completed`) |
| what this example leaves behind, checked rather than assumed | `GET` | `/$IDX/_count` | -- |
|  | `GET` | `/.tasks/_count` | -- |

`$IDX` is `parcels`.

## Endpoints touched

Path parameters and query strings removed, deduplicated:

- `/`
- `/<var>`
- `/<var>/_bulk`
- `/<var>/_count`
- `/<var>/_delete_by_query`
- `/<var>/_doc/<var>`
- `/<var>/_refresh`
- `/<var>/_search`
- `/<var>/_update/<var>`
- `/<var>/_update_by_query`
- `/_cluster/health/<var>`
- `/_tasks`
- `/_tasks/<var>`

## Not called, and why

Described in `docs/design.md`; left out of `run.sh` because this node's answer
is not yet OpenSearch's:

- `POST /_update_by_query/<task id>/_rethrottle`, `POST /_delete_by_query/<task id>/_rethrottle`
- `POST /_tasks/<task id>/_cancel`
- `slices=auto` / `slices=N` on either job
- `POST /_plugins/_asynchronous_search`, `GET` / `DELETE /_plugins/_asynchronous_search/<id>`
- `"profile": true` on `_search`
